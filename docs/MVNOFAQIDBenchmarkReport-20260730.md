## 12. 정확도 우선 정책 구현과 회귀 결과

FAQ는 가능한 많이 답하는 것보다 잘못된 답변을 내보내지 않는 것이 중요하다는 운영 원칙에
따라 별도의 선택 정책을 추가했다.

- `workspace`: 워크스페이스에 저장된 정책을 따름
- `coverage`: 기존처럼 최고 점수 후보를 우선 선택
- `precision`: 안전 조건을 모두 통과한 경우에만 답변

정확도 우선 정책은 다음 조건을 검사한다.

1. 후보 점수가 워크스페이스 안전 점수 이상인지 확인
2. 키워드, 벡터, 그래프 중 필요한 수 이상의 독립 근거가 있는지 확인
3. 서로 다른 분야의 최고 점수 차이가 충분한지 확인
4. 같은 분야의 상위 후보 점수 차이가 충분한지 확인
5. LLM ID 선택 시 후보 밖 ID, `null`, 낮은 신뢰도, 호출 실패를 모두 거절
6. LLM이 높은 신뢰도를 반환해도 분야 및 후보 충돌 검사를 우회하지 않음
7. 질문 길이는 거절 조건으로 사용하지 않으며, 짧고 의미가 고유한 질문도 답변
8. 여러 의미가 가능한 짧은 질문은 `clarification_question`으로 확인 질문 반환

LLM 최소 신뢰도 0.80으로 적용했다.

독립된 블라인드 평가가 아니라 수정 후 회귀 결과다. 실제 상담 질문으로 구성한 새 평가셋을
별도로 만들어 동일 기준을 통과해야 운영 품질로 확정할 수 있다.

## 13. 결론

질문과 답변 ID만 있는 자료도 FAQ와 그래프를 구축할 수는 있지만, ID당 등록 질문 4개로는
실서비스 수준의 세부 의도 분류가 어렵다. 특히 유심·개통, 번호이동·명의변경,
로밍 신청·차단·요금처럼 가까운 의도가 서로 경쟁한다.

다음 개선이 필요하다.

1. 답변 ID당 10~20개의 실제 상담 표현을 확보한다.
2. AI가 등록 질문만 보고 동의어와 구어체를 제안하되 운영자 승인 후 반영한다.
3. 현재 구현한 정확도 우선 정책을 실제 상담 질문 블라인드 평가로 다시 검증한다.
4. `알뜰폰 고객센터 범위인지`를 먼저 판단하는 별도 도메인 거절 모델을 검토한다.
5. 새로 추가한 `clarification_question`을 콜봇의 후속 발화와 연결하고 재질의 문맥을 유지한다.
6. 응답시간이 중요한 채널은 그래프·정확도 우선을 먼저 적용하고, 중요 의도만 LLM 최종판정을 사용한다.

기본 조회 방식 비교는 테스트 질문을 FAQ 힌트에 추가하거나 결과에 맞춰 FAQ 데이터를
변경하지 않은 합성 홀드아웃 평가다. 정확도 우선 최종 수치는 안전 규칙 보완 후의 회귀
결과다. 실서비스 품질 판정에는 작성자가 분리된 평가셋이나 익명화한 실제 상담 질문으로
추가 블라인드 검증이 필요하다.
